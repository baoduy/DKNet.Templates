# Customer Profiles — API Reference

Base URL: `/v1/customer-profiles` (no `/api` prefix — the route is `/v{version}{GroupEndpoint}`
from `CustomerProfileV1Endpoint`, `Version = 1`, `GroupEndpoint = "/customer-profiles"`).

## Endpoint Summary

| Method | Path | Description | Auth Required |
|--------|------|-------------|---------------|
| `GET` | `/` | List all profiles (paged) | ✓ Bearer |
| `GET` | `/{id:guid}` | Get profile by ID | ✓ Bearer |
| `POST` | `/` | Create a new profile | ✓ Bearer |
| `PUT` | `/` | Update an existing profile | ✓ Bearer |
| `DELETE` | `/` | Delete a profile | ✓ Bearer |

There is no approve/reject workflow — `CustomerProfile` has no `Status` field. `DELETE` removes
the row; there is no soft-delete.

> Auth is off by default in the shipped template (`FeatureManagement:RequireAuthorization = false`)
> — every route above requires a bearer token only once you turn that flag on.

## GET /v1/customer-profiles

Returns a paginated list of profiles.

**Query Parameters**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `pageNumber` | `int` | No | Page number (default `1`; values `< 1` are clamped to `1`) |
| `pageSize` | `int` | No | Items per page (default `20`; values `< 1` are clamped to `20`; values `> 100` are clamped to `100`) |

**Response: 200 OK**

```json
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "name": "Jane Smith",
      "email": "jane.smith@example.com",
      "membershipNo": "MEM-2025-00001",
      "phone": "+61412345678",
      "createdBy": "user-abc123",
      "createdOn": "2025-01-01T10:00:00Z"
    }
  ],
  "pageNumber": 1,
  "pageSize": 20,
  "pageCount": 1,
  "totalItemCount": 1,
  "hasNextPage": false,
  "hasPreviousPage": false
}
```

**curl**

```bash
curl -X GET "https://localhost:7001/v1/customer-profiles?pageNumber=1&pageSize=20" \
  -H "Authorization: Bearer {token}"
```

## GET /v1/customer-profiles/{id}

Returns a single profile by its GUID identifier, or `404` if not found.

```bash
curl -X GET "https://localhost:7001/v1/customer-profiles/3fa85f64-5717-4562-b3fc-2c963f66afa6" \
  -H "Authorization: Bearer {token}"
```

## POST /v1/customer-profiles

Creates a new customer profile. `membershipNo` is auto-generated by `IMembershipService` — the
request has no `membershipNo` field. Requires `X-Idempotency-Key` (the endpoint calls
`.RequiredIdempotentKey()`).

**Request Body** — validated by `CreateProfileCommandValidator`

```json
{
  "name": "Jane Smith",
  "email": "jane.smith@example.com",
  "phone": "+61412345678"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `name` | `string` | ✓ | Length 6–100 |
| `email` | `string` | ✓ | Valid email format; length 1–1000; unique across profiles |
| `phone` | `string` | ✓ | Length 6–50 |

**Response: 201 Created**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Jane Smith",
  "email": "jane.smith@example.com",
  "membershipNo": "MEM-2025-00001",
  "phone": "+61412345678",
  "createdBy": "user-abc123",
  "createdOn": "2025-01-15T10:00:00Z"
}
```

**Error Responses**

| Status | Description |
|--------|-------------|
| `400` | Validation failed (missing/invalid `name`, `email`, or `phone`) |
| `409` | A profile with this email already exists |
| `401` | Missing or invalid bearer token |

**curl**

```bash
curl -X POST "https://localhost:7001/v1/customer-profiles" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: $(uuidgen)" \
  -d '{"name":"Jane Smith","email":"jane.smith@example.com","phone":"+61412345678"}'
```

## PUT /v1/customer-profiles

Updates an existing profile. Handled by `UpdateProfileCommandHandler` — **not validated by
FluentValidation** (no validator exists for `UpdateProfileRequest` today). `email`/`name`/`phone`
are optional; a `null` or missing field leaves the current stored value unchanged.

**Request Body**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Jane M. Smith",
  "phone": "+61498765432"
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | `guid` | ✓ | Profile to update |
| `name` | `string?` | No | `null`/omitted keeps the current value |
| `email` | `string?` | No | `null`/omitted keeps the current value; no uniqueness re-check on update |
| `phone` | `string?` | No | `null`/omitted keeps the current value |

**Response: 200 OK** — updated `CustomerProfileDto`, or a failed result (`404`-shaped) when `id`
does not resolve to an existing profile.

**curl**

```bash
curl -X PUT "https://localhost:7001/v1/customer-profiles" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","name":"Jane M. Smith","phone":"+61498765432"}'
```

---

## DELETE /v1/customer-profiles

Deletes a profile by `id` in the request body. `DeleteProfileCommandHandler` calls
`repository.Delete(profile)` — this is a hard delete; the row is gone, not flagged.

**Request Body**

```json
{ "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6" }
```

**curl**

```bash
curl -X DELETE "https://localhost:7001/v1/customer-profiles" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"id":"3fa85f64-5717-4562-b3fc-2c963f66afa6"}'
```

## Common Error Format (ProblemDetails)

All error responses follow RFC 7807 `ProblemDetails`:

```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "traceId": "00-a1b2c3d4e5f6...-00",
  "errors": {
    "Email": ["'Email' must not be empty.", "'Email' is not a valid email address."]
  }
}
```
