# Customer Profiles — API Reference

Base URL: `/api/v1/customer-profiles`

## Endpoint Summary

| Method | Path | Description | Auth Required |
|--------|------|-------------|---------------|
| `GET` | `/` | List all profiles (paged) | ✓ Bearer |
| `GET` | `/{id:guid}` | Get profile by ID | ✓ Bearer |
| `POST` | `/` | Create a new profile | ✓ Bearer |
| `PUT` | `/{id:guid}` | Update an existing profile | ✓ Bearer |
| `DELETE` | `/{id:guid}` | Soft-delete a profile | ✓ Bearer |
| `PATCH` | `/{id:guid}/approve` | Approve a pending profile | ✓ Bearer |
| `PATCH` | `/{id:guid}/reject` | Reject a pending profile | ✓ Bearer |

---

## GET /api/v1/customer-profiles

Returns a paginated list of all active (non-deleted) profiles.

> **Behavior change (DRK-500):** since adopting `DKNet.AspCore.Extensions`' `MapGetList`, both query
> parameters below are **required** — a paramless call that used to return `200 OK` with 100 items now
> returns `400 Bad Request`. The default page size also dropped from 100 to 20 (applied only when
> `pageSize` is supplied as `0` or negative, since the parameter itself has no default).

**Query Parameters**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `pageNumber` | `int` | **Yes** | Page number (values `< 1` are clamped to `1`) |
| `pageSize` | `int` | **Yes** | Items per page (values `< 1` are clamped to `20`) |

**Response: 200 OK**

```json
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "name": "Jane Smith",
      "email": "jane.smith@example.com",
      "membershipNo": "MEM-2025-00001",
      "phone": "+61412345678",
      "status": "Approved",
      "createdAt": "2025-01-01T10:00:00Z",
      "createdBy": "user-abc123"
    }
  ],
  "pageNumber": 1,
  "pageSize": 20,
  "pageCount": 1,
  "totalItemCount": 1
}
```

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `Bad Request` | `pageNumber` or `pageSize` missing from the query string |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X GET "https://localhost:7001/api/v1/customer-profiles?pageNumber=1&pageSize=20" \
  -H "Authorization: Bearer {token}"
```

## POST /api/v1/customer-profiles

Creates a new customer profile. The membership number is auto-generated by `IMembershipService`.

> Supports idempotency via `X-Idempotency-Key` header to prevent duplicate creation.

**Request Body**

```json
{
  "name": "Jane Smith",
  "email": "jane.smith@example.com",
  "phone": "+61412345678"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `name` | `string` | ✓ | Max 150 chars |
| `email` | `string` | ✓ | Valid email format; unique across profiles |
| `phone` | `string` | No | Max 25 chars |

**Response: 201 Created**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Jane Smith",
  "email": "jane.smith@example.com",
  "membershipNo": "MEM-2025-00001",
  "phone": "+61412345678",
  "status": "Pending",
  "createdAt": "2025-01-15T10:00:00Z",
  "createdBy": "user-abc123"
}
```

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `ValidationError` | Missing required fields or email format invalid |
| `409` | `Conflict` | A profile with this email already exists |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X POST "https://localhost:7001/api/v1/customer-profiles" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: unique-request-id-123" \
  -d '{"name":"Jane Smith","email":"jane.smith@example.com","phone":"+61412345678"}'
```

## PUT /api/v1/customer-profiles/{id}

Updates name, email, and phone on an existing profile.

**Request Body**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Jane M. Smith",
  "email": "jane.m.smith@example.com",
  "phone": "+61498765432"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `id` | `guid` | ✓ | Must match path `{id}` |
| `name` | `string` | ✓ | Max 150 chars |
| `email` | `string` | ✓ | Valid email; unique (excluding current profile) |
| `phone` | `string` | No | Max 25 chars |

**Response: 200 OK** — returns updated `CustomerProfileDto`

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `ValidationError` | Validation failed |
| `404` | `NotFound` | Profile not found |
| `409` | `Conflict` | Email already used by another profile |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X PUT "https://localhost:7001/api/v1/customer-profiles/3fa85f64-5717-4562-b3fc-2c963f66afa6" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","name":"Jane M. Smith","email":"jane.m.smith@example.com"}'
```

## DELETE /api/v1/customer-profiles/{id}

Soft-deletes a profile (`IsDeleted = true`). The record is retained in the database for audit.

**Response: 204 No Content**

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `404` | `NotFound` | Profile not found |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X DELETE "https://localhost:7001/api/v1/customer-profiles/3fa85f64-5717-4562-b3fc-2c963f66afa6" \
  -H "Authorization: Bearer {token}"
```

## PATCH /api/v1/customer-profiles/{id}/approve

Approves a `Pending` profile. Sets `Status = Approved`.

**Request Body**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "reason": "KYC documents verified successfully"
}
```

**Response: 200 OK** — returns updated `CustomerProfileDto` with `status = "Approved"`

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `InvalidOperation` | Profile is not in `Pending` status |
| `404` | `NotFound` | Profile not found |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X PATCH "https://localhost:7001/api/v1/customer-profiles/3fa85f64-5717-4562-b3fc-2c963f66afa6/approve" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","reason":"KYC documents verified"}'
```

## PATCH /api/v1/customer-profiles/{id}/reject

Rejects a `Pending` profile. Sets `Status = Rejected`. Reason is required.

**Request Body**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "reason": "Incomplete documentation"
}
```

**Response: 200 OK** — returns updated `CustomerProfileDto` with `status = "Rejected"`

**Error Responses**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `InvalidOperation` | Profile is not in `Pending` status, or reason is empty |
| `404` | `NotFound` | Profile not found |
| `401` | `Unauthorized` | Missing or invalid bearer token |

**curl**

```bash
curl -X PATCH "https://localhost:7001/api/v1/customer-profiles/3fa85f64-5717-4562-b3fc-2c963f66afa6/reject" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","reason":"Incomplete documentation"}'
```

## Common Error Format (ProblemDetails)

All error responses follow RFC 7807 `ProblemDetails`:

```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "traceId": "00-a1b2c3d4e5f6...-00",
  "errors": {
    "Email": ["'Email' must not be empty.", "'Email' is not a valid email address."]
  }
}
```
